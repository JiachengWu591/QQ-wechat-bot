# 枢

以 Claude 为内核的 QQ 和微信智能体桌面程序，只给自己用。“枢”是暂定名。

## 当前进度

M2 的 QQ 官方机器人已经真实联调，并连续试运行了 16 小时以上。M3 的微信指令通道和文档生成已经和真实微信联调。M4 的主流程已经和真实微信联调：在后台发现工作群里的 @、读取允许的群、写回复草稿并提醒，你批准后发到群里。目前只在一个测试群上验证过，还没有用在真实工作群上。读合并转发的聊天记录正在做：读取已经在真实微信上跑通，一份约 60 条的记录 16 屏全部对齐，没有漏也没有重复；经过私聊机器人的完整流程还没有实测。接入方式的验证结果见 [spikes/README.md](spikes/README.md)。

## 运行

```bash
pnpm install
```

桌面程序（需要 Rust 和 Visual Studio C++ 构建工具）：

```bash
pnpm --filter @shu/desktop tauri dev
```

只用浏览器开发界面：

```bash
pnpm dev
```

然后打开 <http://127.0.0.1:5173>。

API key 从 `spikes/.env.local` 读取；没有 key 也能启动，只是 bot 无法回复。开发数据在 `.dev/`，不会进 git。

### 安装包

```bash
pnpm package
```

生成 `apps/desktop/src-tauri/target/release/bundle/nsis/Shu_0.1.0_x64-setup.exe`，约 25 MB。安装只装给当前用户，不需要管理员权限。

在从开始菜单打开的终端里安装：

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\install.ps1
```

第一次安装时，它会把开发版的数据和 `spikes\.env.local` 复制到装好的版本的数据目录（已经有就不动），然后静默安装并启动。不要在 Claude 这类打包应用的终端里运行：Windows 会把它在 AppData 下写的东西都转到那个应用自己的容器里，别的程序看不到，开机启动也不生效。脚本发现在这种终端里会直接停下。

- 安装包里带了打成一个文件的引擎和它要用的 Node（打包时用本机的 Node，至少 24 版），装好后不再需要这个目录，也不需要电脑上装 Node。打包时会在装好的 Node 上先跑一遍冒烟测试：SQLite、Excel、Word、图片切分和读微信窗口的脚本。
- 程序装在 `%LOCALAPPDATA%\Shu`。数据在另一个地方，`%LOCALAPPDATA%\com.shu.console`，key 从那里的 `.env.local` 读，和开发版的 `.dev/` 是两份。卸载时只有勾选删除应用数据才会删掉数据。两个版本不能同时开：后开的那个只会把先开的窗口叫出来。
- 控制台的“开机启动”打开后，登录 Windows 时自动启动，窗口不弹出来，在托盘里。另有“启动后自动打开总闸”，默认关着；引擎出错重启后总闸总是关的。开发版不能设开机启动。
- 改了代码要重新打包、重新安装才会生效。

可以用环境变量调整的设置：

| 变量 | 默认值 | 作用 |
|---|---|---|
| `SHU_DAILY_LIMIT_USD` | 3 | 群聊每日预算 |
| `SHU_OWNER_DAILY_LIMIT_USD` | 5 | 主人私聊里做工作的每日预算 |
| `SHU_MODEL` | `claude-opus-5-5` | 还没在控制台选过模型时用哪个。选过之后以控制台为准 |
| `SHU_CHANNELS` | `qq,wechat,sim` | 启用哪些通道。同一个 QQ 机器人不能同时连两份，再开一份测试时要去掉 `qq` |
| `SHU_ENGINE_PORT`、`SHU_WEB_PORT` | 47821、5173 | 开发时的端口，再开一份时要换掉 |
| `SHU_ENV_FILE` | `spikes/.env.local` | 开发时从哪里读 key |
| `SHU_WECHAT_SCAN_SECONDS` | 15 | 多久读一次微信窗口的左栏 |

## 微信指令

扫码登录是在控制台的微信卡片上做的，扫码的那个微信就是主人。之后在微信里私聊这个机器人：

- 直接说要做什么，比如总结一段内容、做个表格、写份报告。做好的文件会发回微信。
- 可以发文件和图片，手机长截图会切成几段读。文件存在工作区的 `inbox/`，生成的结果在 `files/`。
- 发“取消”或 `/cancel` 可以停止进行中的任务。

这个通道是腾讯给 OpenClaw 用的接口，并没有公开支持直接调用，随时可能变动或被限制。它只能和本人私聊，不能进群，也读不到其他聊天。

## 微信工作群

在控制台的“微信工作群”面板打开开关后，程序定时看一次微信窗口的左栏，发现“有人@我”就记到活动里，并通过上面的通道提醒你。

不在允许名单里的群只提醒，不会被点开。允许的群有人 @ 你时，程序会：

1. 点开那一行。这个群会被标成已读。你正在用微信时不点，等你停下来；你自己先点开了就不再读。
2. 核对标题，再截最多 3 屏聊天区，交给 Claude 读。每张图都用它自己的标题再核对一次，对不上就什么都不发。
3. 把谁说了什么、概要和回复草稿发到你手机上。费用算在“我的工作”的预算里，预算用完就只提醒，不点开。
4. 草稿放进控制台的“待确认”，同一个群新的草稿会替换旧的。

只有你在“待确认”里点了发送才会发，这时程序会：

1. 检查草稿，还有【】、换行或 @ 就不发。打在正文里的 @ 只是普通文字，对方收不到提醒。要 @ 人就填卡片上的“同时 @”，程序会从成员列表里选，选中的不是这个名字就停下。名字要填群里显示的（你的备注或群昵称），微信号搜不到。
2. 等你约 3 秒不碰键盘鼠标，再切到微信。发完切回原来的窗口。
3. 打开这个群，标题核对不上就停。
4. 输入框里已经有你没发的文字就停，免得一起发出去。
5. 逐字打字，不碰剪贴板，再核对一遍标题和输入框，然后按回车。
6. 读屏确认发出去了。确认不了就告诉你“不确定”，不自动重发。这时要你确认没发出去，才能再发一次。

在第 5 步按回车之前停下，都不会发出任何消息。

- 微信主窗口要开着，不能最小化，盖在别的窗口后面没关系。
- 只读得到左栏可见的那几行，排到下面的聊天发现不了。
- 开始读取时已经存在的 @ 不提醒。同一个 @ 只提醒一次。
- 手机上已经看过的 @ 没有标记，所以不会触发。

看一次左栏约 0.3 秒，读取程序约占 140 MB 内存。

### 读合并转发的聊天记录

微信里不能把聊天记录转发给机器人，所以要这样用：

1. 把聊天记录“合并转发”给自己的**文件传输助手**，手机或电脑上都行。
2. 私聊机器人，比如说“总结一下我转发的聊天记录”。

“微信工作群”的开关要开着。程序会：

1. 点开文件传输助手，已经开着就不点。你正在用微信时，等你停下几秒再点。
2. 点开最下面那条聊天记录。记录窗口压在所有窗口后面，不抢焦点。
3. 一页页往下翻到结尾，把相邻两页对齐后拼起来，切成几张图，读完关掉窗口。
4. 让 Claude 逐条转写，这次调用不带工具。转写存进工作区的 `inbox/`，再交给私聊里的模型去总结。之后可以接着问，或者让它做成表格。

- 每屏约 2 秒，最多读 40 屏，再长就只读前面一部分，并告诉你没读完。
- 有对不齐的接缝时，那里会整页保留，并告诉你可能有重复或遗漏。
- 转写和总结的费用都算在“我的工作”的预算里。

## 结构

| 路径 | 内容 |
|---|---|
| `packages/protocol` | 引擎和控制台共用的类型和指令格式 |
| `packages/engine` | 中枢引擎：权限、总闸、会话、预算、存储、本机接口 |
| `apps/desktop` | 控制台界面（React） |
| `spikes` | M0 的一次性验证脚本，不是产品代码 |

## 安全边界

这些规则在 `packages/engine/test` 里有回归测试，改动相关代码时要保持通过：

- 权限只看发送者的账号 ID，不看显示名，也不看在哪个群。
- 一轮对话的权限取上下文里最低的那个。群聊里连主人也拿不到主人专用工具，因为回复全群可见。
- 工具在提供给模型时和实际调用时各检查一次，不靠模型自觉。
- 所有发出的消息和文件都经过同一个闸门。总闸一关，已经写好的回复也发不出去。
- 没有 shell。文件工具只能碰工作区，只有主人的私聊拿得到；表格公式只能做计算，不能联网或启动程序。
- 只有主人私聊发来的文件才会下载。文件内容标记为资料，里面的指令不照做。
- 常驻的读微信窗口程序能截图、识别文字、点左栏的一行、滚动聊天，以及打开、滚动和关掉聊天记录窗口。它没有打字或发送的代码，也拿不到前台，图片不写到磁盘。模型只能通过主人私聊里的一个工具用到它，而这个工具只做一件事：读文件传输助手里最新的那份聊天记录。
- 能打字的是另一个程序，只有主人在控制台批准一条回复时才启动一次，发完就退出。总闸一关立刻结束它，还没按回车就发不出去。模型调用不到它，也没有办法自动批准。
- 只有控制台里允许的群才会被点开。发给 Claude 的每张图，都要先核对图里的标题。
- 读群聊内容的那次调用不带任何工具。群名和群聊内容都是别人写的，所以提醒不写进聊天记录，有工具的模型看不到它们。
- 聊天记录是例外：主人要求总结，转写就得交给私聊里的模型。转写本身由不带工具的调用完成，交回时用 JSON 包起来，并注明内容是别人写的资料，不是主人的指令。私聊里的工具发出的文件只会到主人自己那里。
- 总闸关闭期间收到的消息不保存，也不会进入之后的上下文。
- 本机接口只监听 127.0.0.1，需要令牌，并检查来源页面。
- 桌面程序把自己放进 Windows Job Object，退出或崩溃时会回收引擎和它启动的所有子进程。引擎崩溃后自动重启，但重启后总闸是关的，不会自己恢复运行。
