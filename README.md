# 枢 · QQ / 微信 Claude 智能体

以 Claude 为内核的 Windows 桌面程序，把 QQ 和微信接到同一个“大脑”上，只给自己用。“枢”是暂定名。

A personal Windows desktop agent that connects QQ and WeChat to Claude, built with Tauri, React and Node.js. The interface and docs are in Chinese.

> [!WARNING]
> 这是个人项目，和腾讯、Anthropic 都没有关系。微信部分用的是腾讯没有公开支持的 iLink 接口，加上读写微信窗口，随时可能失效，也可能违反平台规则，导致账号受限。使用风险自负。

## 能做什么

- **QQ 群聊和私聊**：接入 QQ 官方机器人。群里 @ 它可以闲聊，需要时联网搜索，发链接给它会读网页。权限按账号区分，群友用不到本机的工具。你在私聊里可以发图片和文件给它看。
- **群里的小工具**：掷骰子、抽签和随机点名、群投票、猪猪池抽卡、记住每个人想被叫的外号。
- **微信私聊指令**：通过微信 ClawBot 和你本人私聊。可以让它总结内容、做 Excel 表格、写 Word 文档，做好的文件直接发回微信。手机长截图会切成几段来读。
- **微信工作群助手**：在后台看微信窗口，发现工作群里有人 @ 你，就读聊天内容，把概要和回复草稿发到你手机上。你在手机上回复代码，或者在控制台点发送，它才会发到群里，并且能真正 @ 到人。
- **读合并转发的聊天记录**：把聊天记录合并转发给自己的文件传输助手，再让它总结。
- **人设**：在控制台给它写人设卡和示例对话，让它在聊天里说话更有人味。自带一份性格参考银狼的草稿。
- **控制台**：总闸、各通道开关、模型切换（Opus、Sonnet、Haiku）、每日预算、待确认、活动记录。可以打成安装包，开机启动。

## 工作方式

| 部分 | 做法 |
|---|---|
| QQ | QQ 官方机器人的 WebSocket 网关 |
| 微信私聊 | iLink 长轮询，也就是微信 ClawBot 给 OpenClaw 用的接口 |
| 微信工作群 | 用 Windows 自带的 OCR 读左栏的 @ 标记，向窗口发消息来点开和滚动，截聊天区交给 Claude 读。打字发送是另一个脚本，只在你批准时启动一次 |
| 大脑 | 直接调用 Anthropic API，只给模型几个范围很窄的工具，没有 shell |
| 外壳 | Tauri 2 加 React 控制台，Node 引擎由外壳启动和看护 |

不解密微信数据库，不读微信进程的内存，也不注入 hook。

## 当前进度

M2 的 QQ 官方机器人已经真实联调，并连续试运行了 16 小时以上。M3 的微信指令通道和文档生成已经和真实微信联调。M4 的主流程已经和真实微信联调：在后台发现工作群里的 @、读取允许的群、写回复草稿并提醒，你批准后发到群里。目前只在两个测试群上验证过，群里另一位成员是自己的小号，还没有用在真实工作群上。读合并转发的聊天记录已经在真实微信上从手机走通：一份约 60 条的记录 16 屏全部对齐，没有漏也没有重复。在手机上回复草稿的代码就能发到群里，也在测试群上走通了。程序可以打成安装包，开机启动。接入方式的验证结果见 [spikes/README.md](spikes/README.md)。

## 运行

需要：

- Windows 10 或 11。读写微信窗口的部分只能在 Windows 上用。
- Node.js 24 或更高版本，以及 pnpm。
- Rust 和 Visual Studio C++ 构建工具。只有桌面外壳需要，只用浏览器开发界面时不用装。
- Anthropic API key。QQ 机器人的 AppID 和 AppSecret 可选，微信扫码登录。

```bash
pnpm install
```

把 `spikes/.env.example` 复制成 `spikes/.env.local`，填上 key。`.env.local` 不会进 git。

桌面程序：

```bash
pnpm --filter @shu/desktop tauri dev
```

只用浏览器开发界面：

```bash
pnpm dev
```

然后打开 <http://127.0.0.1:5173>。

API key 从 `spikes/.env.local` 读取；没有 key 也能启动，只是 bot 无法回复。开发数据在 `.dev/`，不会进 git。

只开模拟聊天，不连 QQ 和微信，也不读微信窗口，数据和端口都单独一份，可以和装好的版本同时开：

```bash
node --env-file=scripts/sim-only.env scripts/dev.mjs
```

然后打开 <http://127.0.0.1:5184>。数据在 `.dev/sim-only/`。

### 安装包

```bash
pnpm package
```

生成 `apps/desktop/src-tauri/target/release/bundle/nsis/Shu_0.1.0_x64-setup.exe`，约 25 MB。安装只装给当前用户，不需要管理员权限。

在从开始菜单打开的终端里安装：

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\install.ps1
```

第一次安装时，它会把开发版的数据和 `spikes\.env.local` 复制到装好的版本的数据目录（已经有就不动），然后静默安装并启动。不要在 Claude 这类打包应用的终端里运行：Windows 会把它在 AppData 下写的东西都转到那个应用自己的容器里，别的程序看不到，开机启动也不生效。脚本发现在这种终端里会直接停下。

- 安装包里带了打成一个文件的引擎和它要用的 Node（打包时用本机的 Node，至少 24 版），装好后不再需要这个目录，也不需要电脑上装 Node。打包时会在装好的 Node 上先跑一遍冒烟测试：SQLite、Excel、Word、图片切分和读微信窗口的脚本。
- 程序装在 `%LOCALAPPDATA%\Shu`。数据在另一个地方，`%LOCALAPPDATA%\com.shu.console`，key 从那里的 `.env.local` 读，和开发版的 `.dev/` 是两份。卸载时只有勾选删除应用数据才会删掉数据。两个版本不能同时开：后开的那个只会把先开的窗口叫出来。
- 控制台的“开机启动”打开后，登录 Windows 时自动启动，窗口不弹出来，在托盘里。另有“启动后自动打开总闸”，默认关着；引擎出错重启后总闸总是关的。开发版不能设开机启动。
- 改了代码要重新打包、重新安装才会生效。

可以用环境变量调整的设置：

| 变量 | 默认值 | 作用 |
|---|---|---|
| `SHU_DAILY_LIMIT_USD` | 3 | 群聊每日预算 |
| `SHU_OWNER_DAILY_LIMIT_USD` | 5 | 主人私聊里做工作的每日预算 |
| `SHU_MODEL` | `claude-opus-5-5` | 还没在控制台选过模型时用哪个。选过之后以控制台为准 |
| `SHU_CHANNELS` | `qq,wechat,sim` | 启用哪些通道。同一个 QQ 机器人不能同时连两份，再开一份测试时要去掉 `qq` |
| `SHU_ENGINE_PORT`、`SHU_WEB_PORT` | 47821、5173 | 开发时的端口，再开一份时要换掉 |
| `SHU_ENV_FILE` | `spikes/.env.local` | 开发时从哪里读 key |
| `SHU_WECHAT_SCAN_SECONDS` | 15 | 多久读一次微信窗口的左栏 |
| `SHU_DATA_DIR` | `.dev/data` | 开发时数据放在哪里，相对于仓库目录 |

## 微信指令

扫码登录是在控制台的微信卡片上做的，扫码的那个微信就是主人。之后在微信里私聊这个机器人：

- 直接说要做什么，比如总结一段内容、做个表格、写份报告。做好的文件会发回微信。
- 可以发文件和图片，手机长截图会切成几段读。文件存在工作区的 `inbox/`，生成的结果在 `files/`。
- 发“取消”或 `/cancel` 可以停止进行中的任务。

这个通道是腾讯给 OpenClaw 用的接口，并没有公开支持直接调用，随时可能变动或被限制。它只能和本人私聊，不能进群，也读不到其他聊天。

## 微信工作群

在控制台的“微信工作群”面板打开开关后，程序定时看一次微信窗口的左栏，发现“有人@我”就记到活动里，并通过上面的通道提醒你。

不在允许名单里的群只提醒，不会被点开。允许的群有人 @ 你时，程序会：

1. 点开那一行。这个群会被标成已读。你正在用微信时不点，等你停下来；你自己先点开了就不再读。
2. 核对标题，再截最多 3 屏聊天区，交给 Claude 读。每张图都用它自己的标题再核对一次，对不上就什么都不发。
3. 把谁说了什么、概要和回复草稿发到你手机上。费用算在“我的工作”的预算里，预算用完就只提醒，不点开。
4. 草稿放进控制台的“待确认”，同一个群新的草稿会替换旧的。

只有你批准了才会发，有两种批准方式：在控制台的“待确认”里点发送，或者在手机上回复提醒里的代码。每条草稿有一个两个字母加两个数字的代码，比如 `KQ27`：

- `发 KQ27`：按草稿发，带上提醒里说的 @。
- `发 KQ27` 再空一格写上一整句：发你改过的内容。
- 草稿里有【】时不能直接发。提醒后面会再单独发一条“发 KQ27 草稿全文”，长按复制，把【】改好再发回来。原样发回来还是会被拦下。
- 代码后面加 `@名字` 换一个人 @，加 `不@` 就不 @。
- `不发 KQ27`：不发了。
- `重发 KQ27`：上一次“不确定有没有发出去”，你看过确实没发出去之后，用它再发一次。

全角的字母、数字、空格和 @ 也认，你写的内容原样发出。如果代码后面写的正好是提醒里的说明文字，比如“改好的整句”，就不发，因为这种情况真的发生过一次。这些回复只认你本人的私聊，在模型看到之前就处理掉，不进聊天记录，回给你的结果也不进。每个回复都会在活动里记一行，只写结果，不写草稿内容。同一个群有了新草稿，旧代码就失效。

不管哪种方式批准，程序都会：

1. 检查草稿，还有【】、换行或 @ 就不发。打在正文里的 @ 只是普通文字，对方收不到提醒。要 @ 人就填卡片上的“同时 @”，程序会从成员列表里选，选中的不是这个名字就停下。名字要填群里显示的（你的备注或群昵称），微信号搜不到。
2. 等你约 3 秒不碰键盘鼠标，再切到微信。发完切回原来的窗口。
3. 打开这个群，标题核对不上就停。
4. 输入框里已经有你没发的文字就停，免得一起发出去。
5. 逐字打字，不碰剪贴板，再核对一遍标题和输入框，然后按回车。
6. 读屏确认发出去了。确认不了就告诉你“不确定”，不自动重发。这时要你确认没发出去，才能再发一次。

在第 5 步按回车之前停下，都不会发出任何消息。

- 微信主窗口要开着，不能最小化，盖在别的窗口后面没关系。
- 只读得到左栏可见的那几行，排到下面的聊天发现不了。
- 开始读取时已经存在的 @ 不提醒。同一个 @ 只提醒一次。
- 手机上已经看过的 @ 没有标记，所以不会触发。

看一次左栏约 0.3 秒，读取程序约占 140 MB 内存。

### 读合并转发的聊天记录

微信里不能把聊天记录转发给机器人，所以要这样用：

1. 把聊天记录“合并转发”给自己的**文件传输助手**，手机或电脑上都行。
2. 私聊机器人，比如说“总结一下我转发的聊天记录”。

“微信工作群”的开关要开着。程序会：

1. 点开文件传输助手，已经开着就不点。你正在用微信时，等你停下几秒再点。
2. 点开最下面那条聊天记录。记录窗口压在所有窗口后面，不抢焦点。
3. 一页页往下翻到结尾，把相邻两页对齐后拼起来，切成几张图，读完关掉窗口。
4. 让 Claude 逐条转写，这次调用不带工具。转写存进工作区的 `inbox/`，再交给私聊里的模型去总结。之后可以接着问，或者让它做成表格。

- 每屏约 2 秒，最多读 40 屏，再长就只读前面一部分，并告诉你没读完。
- 有对不齐的接缝时，那里会整页保留，并告诉你可能有重复或遗漏。
- 转写和总结的费用都算在“我的工作”的预算里。

## 群里的小工具

谁都能用，不碰电脑上的任何东西。叫它的时候要 @ 它，或者提到它的名字。

- **掷骰子**：“掷两个骰子”“掷一个 20 面骰”。在 QQ 上，6 面骰（最多 6 个）会发一张骰子滚动后停在结果上的动图，点数先用真随机数定好，动图只是展示。其他骰子照旧用文字。
- **抽签、随机点名**：“火锅、烧烤、日料抽一个”“随机点两个人”。结果是真随机，不是模型自己挑的。
- **投票**：“开个投票：周五吃火锅还是烧烤”，大家 @ 它说“投 1”。每个群同时只有一个投票，24 小时后自动结束。每人一票，可以改；票算在发消息的人头上，别人替不了。只有发起人和主人能提前结束。在 QQ 上，投票会显示成一张带票数条的卡片。QQ 自带的群投票没有给机器人的接口；点一下就能投的按钮要向 QQ 开放平台申请按钮模板。
- **猪猪池抽卡**：“单抽”“来个十连”。卡池里是你挑的猪猪表情图，每张定好几星：
  - 加卡：在 QQ 私聊里把图发给 bot，再说“加进猪猪池，五星，叫猪降临”。改几星、改名、删卡、看清单也都在私聊里说。只有你能改卡池。
  - 支持 png、jpg、gif 和静态的 webp，10 MB 以内，最多 80 张。webp 会转成 png 存起来，因为 QQ 和画图的库都不认 webp；会动的 webp 用不了。每种稀有度至少有一张，才能开抽。同一张图不能加两次。
  - 也可以让 bot 按群里的使用频率帮你挑：在私聊里说“在测试群统计猪猪图”，它就开始记这个群里每张图被谁发过几次。QQ 给图片起的文件名就是图片内容的 md5，所以同一张表情包不管谁发都认得出来，计数不用下载。一张图被至少两个不同的人发过，才会下载一份存成候选（工作区的 `candidates/`）。
  - 说“看看猪猪候选”，bot 会发你一张带编号的总览图，按发的次数排序，并按频率建议稀有度：最少见的一成是五星，接下来三成是四星，其余三星。说“把 1、3 加进去，1 叫猪降临”就按建议的稀有度加进去，也可以自己定几星；说“丢掉 2”就不再出现。说“在测试群停止统计”就关掉。
  - 还可以从 [PigHub](https://pighub.top/)（一个公开的猪猪图网站，作者提供整套图包下载）导入。网站的列表里有每张图的浏览数和下载数，bot 用“看到的人里有多少下载了”来衡量别人用得多不多，这样新图和老图比较公平。用得越少越稀有，按全站排：最少的一成是五星，接下来三成是四星，其余三星。
    - 说“从 PigHub 导入一套”：默认导入 50 张，不会超过卡池的空位。五星、四星、三星的比例和全站一样（1:3:6），每档里随机挑。大约要一两分钟，中途说“取消”会停下，已经加进去的留着。
    - 说“在 PigHub 找期末”：bot 发你一张最多 12 张的编号预览图（不说关键词就随机挑）。说“把 1、3 加进去”就用网站上的名字和建议的稀有度加进去，名字超过 12 个字会截短，重名会加数字。
    - PigHub 上大约一半的 .jpg/.png 其实是 WebP，会照常转成 png。会动的 WebP 和下载不了的图，预览和导入都会跳过，换同一档的下一张；用不了的图下次不会再试。
  - 规则仿照常见的抽卡模拟器：五星 0.6%，第 74 抽起逐渐变高，90 抽内必出；每 10 抽至少一个四星。每个人在每个群的保底单独记。
  - 在 QQ 上会发一张结果图，卡片里就是那张猪猪图，五星金框、四星紫框、三星蓝框。出五星时，还会把那张五星原图单独发出来，GIF 也会动。
  - 图片存在工作区的 `gacha/` 文件夹，是从你发来的图复制过去的，删卡时只删这份复制。
  - 只是游戏，不涉及任何真实的东西。
- **外号**：“以后叫我老王”，它就会这样叫你；“别叫我外号了”就忘掉。只能给自己起，不能叫“主人”“管理员”这类听起来像身份的名字。外号不改变权限。
- **图片怎么发**：骰子动图和五星猪猪原图在 QQ 上作为“素材”上传一次以后反复用（每个机器人最多存 100 张，所以卡池最多 80 张），放在 Markdown 消息里显示；抽卡结果图每次不同，作为富媒体图片上传。图片和卡片只在“自动回复”的聊天里发，因为它们不能先放进“待确认”。发不出去时会退回文字，活动里记下原因。图是用 resvg（编译成 WebAssembly）和 gifenc 在本机画的，中文用系统自带的微软雅黑。WebP 用 @jsquash/webp 解码，它是谷歌 libwebp 的 WebAssembly 版，来自 Squoosh。
- **读链接**：消息里有网页链接时，它会去读，然后总结或回答。网页是在 Anthropic 的服务器上读的，不经过这台电脑。只能读聊天里有人发出来的链接，页面里的其他链接不会再点开。群友读链接和搜索共用每天的联网次数。读一个网页比普通回复贵，用 Opus 实测一次约 $0.12。

## 人设

在控制台的“人设”页里，可以给它写一张人设卡（它是谁、怎么说话、哪些话不说），再配上示例对话（别人说什么、它怎么回）。默认是一份性格参考《崩坏：星穹铁道》银狼的草稿：一张人设卡加 20 组原创示例，默认关着。

- 三种模式：关闭；只在模拟聊天里试，真实的 QQ 和微信照常；所有聊天。
- 你和它的 QQ 私聊也用人设；微信私聊是交代工作的地方（总结、做表格、写文档），不用人设，照常说话。不管在哪里，它做出来的文件、表格和文档都照常书写。
- 在“聊天”页里，bot 的每条回复下面都有“改成这样…”。改成你想要的回复后，它会和上一条别人的消息配成一组，加进示例。改得越多越像。
- 最多 60 条示例，人设卡最多 4000 字，每条示例最多 300 字。
- 人设每次都会带上，但用了提示词缓存。实测用 Opus 时，第一条回复约 $0.012，之后连续聊天每条约 $0.003 到 $0.004。超过 5 分钟没人说话，下一条又要重新写缓存。
- 示例台词要自己写，不要照搬游戏里的原台词。

## 结构

| 路径 | 内容 |
|---|---|
| `packages/protocol` | 引擎和控制台共用的类型和指令格式 |
| `packages/engine` | 中枢引擎：权限、总闸、会话、预算、存储、本机接口 |

## 安全边界

这些规则在 `packages/engine/test` 里有回归测试，改动相关代码时要保持通过：

- 权限只看发送者的账号 ID，不看显示名，也不看在哪个群。
- 一轮对话的权限取上下文里最低的那个。群聊里连主人也拿不到主人专用工具，因为回复全群可见。
- 工具在提供给模型时和实际调用时各检查一次，不靠模型自觉。
- 所有发出的消息和文件都经过同一个闸门。总闸一关，已经写好的回复也发不出去。
- 没有 shell。文件工具只能碰工作区，只有主人的私聊拿得到；表格公式只能做计算，不能联网或启动程序。
- 只有主人私聊发来的文件才会下载，只有一个例外：主人开了统计的 QQ 群里，被至少两个不同的人发过的图片会下载一份，存成猪猪池的候选，只给主人看。别的群、私聊里别人的文件都不下载。文件内容标记为资料，里面的指令不照做。
- 从网上拿图只连 pighub.top 一个网站，地址写死在代码里，只有主人私聊才能用。只发普通的 GET 请求：列表一小时最多取一次，图片一张一张下载，只下载要加进卡池或要放进预览的那些，每张不超过 10 MB。不跟随跳转到别的网站，也不回传任何东西，网站的浏览和下载计数不会被改动。网站给的标题当作资料：去掉控制字符和改变文字方向的字符后，才用作卡名。
- 常驻的读微信窗口程序能截图、识别文字、点左栏的一行、滚动聊天，以及打开、滚动和关掉聊天记录窗口。它没有打字或发送的代码，也拿不到前台，图片不写到磁盘。模型只能通过主人私聊里的一个工具用到它，而这个工具只做一件事：读文件传输助手里最新的那份聊天记录。
- 能打字的是另一个程序，只有主人批准一条回复时才启动一次，发完就退出。批准只能在控制台点，或者主人在私聊里用那条草稿的代码回复；后者只认主人账号的私聊，由程序直接解析，不经过模型。总闸一关立刻结束它，还没按回车就发不出去。模型调用不到它，也没有办法自动批准。
- 只有控制台里允许的群才会被点开。发给 Claude 的每张图，都要先核对图里的标题。
- 读群聊内容的那次调用不带任何工具。群名和群聊内容都是别人写的，所以提醒不写进聊天记录，有工具的模型看不到它们。
- 聊天记录是例外：主人要求总结，转写就得交给私聊里的模型。转写本身由不带工具的调用完成，交回时用 JSON 包起来，并注明内容是别人写的资料，不是主人的指令。私聊里的工具发出的文件只会到主人自己那里。
- 人设只改变说话方式。它在系统提示词里排在规则前面，并且写明规则和工具不因人设改变；谁是主人、能用什么工具仍由代码决定。主人的微信私聊不用人设；QQ 私聊用，但做出来的文件不带人设的口吻。从聊天里存下的示例，“别人说”的部分是别人写的，所以示例以 JSON 放进去，并注明不是指令。有人认真问它是不是 AI，它要承认。
- 投票、抽卡、外号这类替某个人做事的工具，对象由程序按发这条消息的人填上，模型不能指定，所以没法替别人投票或起外号。外号作为资料放进聊天记录，并注明不改变 tier。
- 读网页只能读聊天里出现过的链接，页面和搜索结果里的链接不能再读，免得一个网页把它引到别处。网页内容同样只是资料。
- 工具发的图片和卡片和文字回复走同一个闸门：总闸一关就发不出去。它们发出去就收不回，所以“确认后发送”的聊天里不发。
- 每条回复会记下这一轮用过哪些工具，下一轮的聊天记录里带给模型。模型只看得到之前回复的文字，曾经因此以为自己之前掷的骰子、读的网页是编的，还在群里“更正”。
- 总闸关闭期间收到的消息不保存，也不会进入之后的上下文。
- 本机接口只监听 127.0.0.1，需要令牌，并检查来源页面。
- 桌面程序把自己放进 Windows Job Object，退出或崩溃时会回收引擎和它启动的所有子进程。引擎崩溃后自动重启，但重启后总闸是关的，不会自己恢复运行。
